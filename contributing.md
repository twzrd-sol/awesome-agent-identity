# Contributing

Thanks for considering a contribution. The list is intentionally narrow.

## What belongs

An entry has to address at least one of:

1. Identifying an agent (who is this).
2. Delegating authority to an agent (who authorized this).
3. Authorizing what an agent may do (scope, policy, runtime limits).
4. Holding an agent accountable after the fact (audit chains, behavioral attestation, owner binding).

Generic LLM tooling, generic IAM, generic developer infra: please put it on the list where it belongs.

## What does not

- Marketing copy, taglines, or vendor blurbs. Descriptions should be objective and one sentence.
- Items behind a paywall with no public technical description.
- Items that have not shipped anything (waitlist-only, slide-only, "coming Q3").
- Duplicates. Search the list first.
- Anything you have not actually read or used at least the docs for.

## How to add

Open a PR that adds one entry to the appropriate section. Keep it to one entry per PR unless they cluster naturally. Format:

```
- [Name](permanent-url) - One-sentence description starting with a capital letter and ending with a period.
```

The URL must be the canonical one (vendor product page, IETF datatracker, npm registry, GitHub repo). Not a Medium post, not a Substack roundup, not a mirror.

## How to remove

If an item dies, ships a replacement, or stops being relevant, open a PR that removes it. Removals do not need apology.

## Style

- Keep descriptions short. Title case only for proper nouns.
- Do not write "the best" or "the only" — leave that to the reader.
- Do not stack adjectives. One concrete verb beats three.
- No emoji in entry descriptions.

## Voice

Sound like a person who has read the thing, not like a system that has summarized it. If a description reads as though an LLM produced it, expect a rewrite request.
